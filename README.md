# Agribusiness Data Analysis: Data Cleaning and Preprocessing Strategy

Week 2 of my Junior Data Scientist internship (Agribusiness). This repository turns the cleaning and
preprocessing *strategy* into a small, working and reproducible pipeline, using a **hypothetical (synthetic)
farm-level dataset** that imitates the problems found in real agricultural records.

> The data is generated by code (`src/generate_data.py`) and is **not real farm data**. Because the "true" values
> are known, the pipeline can be checked against them.

## What the pipeline does

| Step | Module | What happens |
|------|--------|--------------|
| 1 | `generate_data.py` | Creates a clean "ground truth" table (1,200 farms) and a damaged raw table (1,245 rows) |
| 2 | `cleaning.py` | Standardizes formats (placeholders, crop names, 3 date formats, area units, numbers stored as text) |
| 3 | `cleaning.py` | Removes duplicates (exact copies and re-typed copies of the same farm) |
| 4 | `cleaning.py` | Applies validity rules (pH 0 to 14, no negative rainfall, area above zero, harvest after sowing) |
| 5 | `cleaning.py` | Handles missing values with group medians and adds `*_was_missing` flags |
| 6 | `cleaning.py` | Treats outliers with a two-tier IQR rule (typing errors replaced, plausible extremes capped) |
| 7 | `cleaning.py` | Creates features (fertilizer per hectare, crop duration, log price) |
| 8 | `preprocessing.py` | One-hot encoding, train/test split (80/20), scaling fitted on the training set only |
| 9 | `evaluate.py` | Compares the cleaned data with the ground truth and writes `outputs/metrics.json` and figures |

Every cleaning action is written to `outputs/cleaning_log.csv`.

## How to run

```bash
pip install -r requirements.txt
python src/run_pipeline.py
python -m unittest discover tests
```

The random seed is fixed (`SEED = 42` in `src/config.py`), so every run produces exactly the same data and results.

## Results (from one run)

| Check | Result |
|-------|--------|
| Rows | 1,245 raw rows to 1,159 clean rows (45 duplicates, 36 rows without yield and 5 without valid area removed) |
| Duplicates | 45 injected, 45 removed |
| Missing values after cleaning | 0 in every column |
| Rainfall imputation error | 97 mm (group median) vs 366 mm (global mean) |
| Market price imputation error | Rs 147 (group median) vs Rs 1,697 (global mean) |
| Soil pH imputation error | about 0.49 for every method (grouping gives no benefit for pH in this data) |
| Yield outliers | 11 of 11 typing errors found; error in crop-wise mean yield fell from 8.96% to 0.08% |

Figures are saved in `outputs/figures/`.

## Reproducibility

- The raw data is never edited by hand; all changes happen in code.
- Thresholds, mappings and rules are kept in `src/config.py`.
- The random seed is fixed, and scaling and imputation values are learned from the training data only (no data leakage).
- Each action is recorded in `outputs/cleaning_log.csv`.

## Limitations

- The dataset is synthetic, so results show how the method behaves, not how it would perform on real data.
- Group medians are simple and can reduce natural variation; model-based imputation could be tried on real data.
- Thresholds (valid ranges, IQR multiplier) should be confirmed with agricultural experts before real use.
